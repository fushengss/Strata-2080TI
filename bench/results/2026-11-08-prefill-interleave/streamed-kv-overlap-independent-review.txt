Verdict
No additional KV-specific host-ready dependency, mapped-flag deadlock or main/slot KV alias blocker was found for the current CUDA/int8/kv-resident32768/max-context262144 configuration with eight independent stage devices, all experts resident, private prefill buffers and the existing stable-state guards. This is permission to continue actual first-use 100k correctness qualification, not a runtime safety guarantee, performance result or deployment approval. Expert residency alone was not used as proof: the KV refill path was traced independently.

Decode graph and authoritative host storage

It is not a demand-filled CPU queue or an on-the-fly mmap/pagefile refill. Global host-byte counters and allocation policy are initialization bookkeeping, not per-window producer state.

The existing PLE/expert-doorbell proof remains separately necessary; this audit found no extra KV host flag that invalidates it. Additional shared-scratch check

For the audited normal path they do not alias prefill: the decode split dispatch2923–2925 requires active_blocks<=0, whereas normal prefill4330–4339 and7675–7684 always passes active n_bid+1>0. At100k the prompt uses its own score/id buffers and the regular wide selection kernel; the optional larger-prompt g_tk_fail scratch is separate from decode split. There is one batch verifier body stream per device, and MTP attention does not use this topk scratch. STRATA_IDX_FP16_CHECK's debug recomputation4383–4386 omits the active bound and also has static diagnostic buffers; it is absent from the current configuration and is explicitly outside this qualification. This finding is not a claim that arbitrary diagnostic flags or multiple prompt readers are safe.

Required runtime qualification and limits
Run the actual frozen mixed100k workload with four100k resident requests beyond32768 KV cells and a long injected prompt. Require complete output/usage equality against the same binary overlap-off, real threaded reader markers with in-read native output progress, all source audits paired/idle/zero dispatch, no CUDA/nonfinite/failed-read errors beyond the narrowly proven HTTP cancellation, normal completion and idle cleanup. A prior short-prompt C8 or serial100k prefill pass cannot substitute. Exercise first-use graph/allocation paths, not only warmed repetitions.

Pinned host traffic still competes for PCIe bandwidth, GPU memory access and CPU memory bandwidth; kernel or allocation stalls remain possible without a deadlock. This static audit does not measure overlap, p99 stalls, bandwidth saturation, page miss rates or performance. Existing capacity/overflow assumptions remain subject to full runtime output parity. It also does not authorize asynchronous snapshot/parking operations: those use separate global helpers audited in park-copy-streams-independent-review.txt.
