Do not compare one v6 arm directly against one v7 arm: the full harness identity
check correctly rejects it. Aggregate two separately qualified within-version
pairs only after confirming the engine/config/library/server and unchanged
finite suite inputs agree. Do not merge individual arm files or relabel previous
failed fixture runs as passed.

The frozen standalone comparator has a completion-check limitation: it compares
the suite_returncodes keys currently present, without independently requiring
metadata.finished_epoch, all manifest-planned suites, or a failure-free ended
parent run. Automatic runner comparison is reached only after completed arms,
so its normal path is safe. For a manual comparator invocation, additionally
require both arm metadata finished, exact planned suite sets with every rc0,
parent ended_epoch and no failure, and membership of the completed arm in the
parent arms list. Review the runner's source/marker/target-head/cleanup proofs,
not only a child suite's return code.

The standalone analysis below independently requires finished arms, complete
planned suite sets, ended parents and no parent failure before publishing any
comparative metrics. It requires case manifests/reports qualified, exact engine,
server, library, base config, full harness, calibration, normalized config, case
plan/fixture/count hashes, unique expected requests, same request/output/channel
hashes, finish reasons and three logical API usage counts. It also rechecks
normal completion and integer count/native predicted_n consistency. A matched
normal EOS cohort remains valid. An unmatched EOS length cannot claim speedup.

Acceptance metrics, declared before candidate results

Use root's predeclared guard: cold AND warm standalone median native read_ms and
TTFT no more than3% worse than the matching off arm; repeat if outside that
range. There are only3 observations per kind and arm, so retain individual
observations/min/max and reverse order if temperature, clocks or cache state
could dominate the result. This is a practical measurement guard, not a
statistical guarantee of zero regression. Standalone fixtures are approximately
100k (actual counts in the results, commonly101139), while finite injected
fixtures are calibrated exactly10000/60000/100000. Label each correctly.

Mixed injected native prompt time and API-visible TTFT need explicit review:
a smaller resident stall does not justify silently worsening prefill admission.
Compare each actual10k/60k/100k injection independently; queue/park/restore/API
costs make TTFT different from native read/prompt time. Native reader read_ms is
another scope, excluding end drain, and cannot replace either API TTFT or the
request's native prompt_ms. Evaluate primary and mixed100k first, then reverse
order with the same request contract before claiming a stable improvement.

Report resident per-lane phase p95/p99/max visible SSE gaps, largest gap clipping
the phase, and collective intervals with no visible SSE from any resident. Keep
both clipped durations and full gap endpoints: clipping can conceal a long gap
spanning a boundary. Preserve all-four actual visible coverage for baseline,
mixed and recovery, including last visible output at/after recovery end. A late
HTTP terminal event does not prove the decoder was active. Show whole-case
actual API completion tokens per elapsed second only after exact workload
parity; it includes initial admission and final drain. Do not infer pure decode
throughput by subtracting prompt/park durations or assigning token timestamps
from bytes. SSE chunk gaps are client-arrival gaps, not token TBT.

All correctness, C8, admission cancel/reuse, BYIELD park/resume/short-first and
budget continuation/wrap tests must qualify, with output hashes and actual
usage/finish reasons paired. Source proof requires one-to-one source markers,
lookahead idle1 and dispatch_delta0; explicitly confirm staged1 was exercised
for this host. read_ok0 is allowed only for the independently approved on-arm
admission cancellation reader. No other failed read or pump can be excused.

GPU nvidia-smi activity is sampled every500ms. Show each card's mean/p10 activity,
actual SM clock, power and throttle fraction over the same SSE phase windows.
A reported100% activity is not proof of peak SM FLOPS, memory bandwidth, or useful
throughput. Seek improved useful output continuity with unchanged prefill, not
an occupancy number in isolation. Hardware clocks/power changes or other GPU
work invalidate a clean scheduling attribution.
