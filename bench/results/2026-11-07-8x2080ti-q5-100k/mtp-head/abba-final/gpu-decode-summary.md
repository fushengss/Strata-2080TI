# 正式 ABBA：decode 区间 GPU 采样

以下使用正式 `01-off / 02-on / 03-on / 04-off` 的 **48 个性能请求**，替代 pilot 读数。cold/warm 各含 off 12、on 12 个请求，每组 code/prose 各半。只分析本地已有文件，没有 GPU 或服务操作。

区间为客户端首次到最后一次收到非空 content。四个 arm 的 GPU 时区均能由同主机 monitor 生命周期唯一校验为 UTC+0；首采样比 ready 晚 74.7–81.5 ms，采样覆盖全部选定窗口。实际各卡采样间隔中位数为 **545–547 ms**，最大间隔约 **695 ms**；每请求每卡 8–18 个样本，两端各裁 1 秒后 5–15 个。

表中为采样点等权均值，合并同状态的两个 ABBA arm；不是每请求均值等权，也不是连续时间积分。prose 窗口更长，贡献更多样本。off/on 列分别为 MTP draft-head 分片关闭/开启；表中只统计 decode 到达区间，不包含整个 prefill。

## 负载变化与采样边界

合并 cold/warm，GPU3 的采样利用率 **17.22%→23.43%**、功耗 **118.49→143.04 W**；GPU5 为 **16.39%→22.79%**、**128.78→151.66 W**；GPU7 为 **46.84%→37.91%**、**211.33→175.41 W**。符合 draft head 从 GPU7 分到 GPU3/5 后的负载转移。

两端各裁 1 秒后，三个目标 GPU 的利用率方向相同：

| GPU | Cold 内部区间 off→on % | Warm 内部区间 off→on % |
|---:|---:|---:|
| 3 | 19.26 → 26.21 | 19.13 → 26.25 |
| 5 | 18.40 → 25.51 | 18.35 → 25.37 |
| 7 | 47.77 → 37.72 | 45.98 → 36.12 |

GPU7 的 cold/warm 完整窗口读数有明显差别，裁边后差别缩小。设备读数的内部统计区间没有记录，边界附近可能覆盖相邻阶段，不能据此断言 cold/warm 的真实 GPU 计算负载不同。裁边只能检查敏感性，不能保证消除污染。

**限制**：约半秒采样不能推出瞬时峰值、SM occupancy、显存带宽、kernel 重叠、critical path 或硬件是否满载。各卡依次查询，并非同时取样；客户端到达时间也不是 GPU 内核时间。利用率和功耗变化支持负载转移观察，不能替代 ABBA 的端到端速度及 prefill 检查，也没有据此计算能量节省。

数据：[gpu-decode-summary.json](gpu-decode-summary.json) 包含逐请求/逐类别/逐卡 full 与 interior 统计、样本数、时钟和来源 SHA256。分析脚本：[gpu_decode_summary.py](../gpu_decode_summary.py)。本报告复核了四份 CSV/metadata、48 份请求和脚本的来源哈希；八个冻结 harness 哈希与正式 manifest 一致。
