# Orca Q8_0 切换与测速

2026-11-19 在 `10.100.3.3` 切换此前使用过的 Orca Qwen3.8-Flash-Next-Uncensored Q8_0。测试沿用 Q5 线上使用的当前引擎、服务器、8 张 RTX 2080 Ti、8 个 batch group、3072-token prefill、INT8 KV 与 MTP 配置。每张卡的功耗上限为 250 W。测试实例仅监听 `127.0.0.1:8080`。

Q5 对照复用此前已保存的实测数据。冷 100k 采用同样三轮测试，短提示 C8/C16 复用相同采样参数和 fixture，混合请求使用同样的容量与事件定义。16 槽饱和场景下，长请求先排队，释放一槽后与剩下 15 路重叠。[Q5 冷 100k 和混合负载](../2026-11-19-gpu-mmq-route/README.md) · [Q5 短提示 decode](../2026-11-18-decode-throughput/README.md)

切换脚本使用同目录的 `run_ab.py`、`prefill_ab.py`、`bench_decode.py` 和 `bench_decode_insert.py`，借用当前 Q5 配置的监听、认证和运行参数，再替换为历史 Q8 的 pack、GGUF、tokenizer 和视觉权重路径。两个原有配置文件均保留。Q8 使用自己的模型名，原 Q5 名称作为兼容别名。[运行脚本](switch_q8.py)

## Q8 启动差异

最初冷加载在准备专家主存补集时触发了 900 秒 READY 超时。随后顺序预热五个 GGUF 文件，把 Q8 READY 上限调到 1800 秒，令专家补集使用普通主存。Q8 使用共享 MTP 输出头，原 Q5 的两项草稿头分片设置仅适用于自有 Q6_K 子集，因此在 Q8 去掉这两个开关，MTP 继续启用。修正后 16 槽测试实例在 226.6 秒完成启动，已通过文本生成检查。[测试实例](raw/test-receipt.json)

GPU1 驻留 2,899 个专家、GPU7 驻留 2,691 个，其余六张卡各 3,072 个。全模型共驻留 24,022 / 24,576，约 97.75%。其余 554 个专家合计约 2.69 GiB，有主存副本。引擎在 prefill 时借用各卡 422 个专家槽，八卡共 3,376 个。借用区域的权重也保留在主存。该配置的性能包含这些搬运及共享 MTP 头的影响。[驻留记录](raw/q8-residency.log)
